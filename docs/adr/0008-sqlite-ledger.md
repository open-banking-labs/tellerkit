# ADR-0008：本地账本用 SQLite

- 状态：已接受
- 日期：2026-11-24

## 背景

P1.4 要把待重放队列与交易审计落盘。候选：SQLite、JSONL 追加文件、嵌入式 KV（sled）。

## 决策

用 **SQLite（rusqlite，bundled）**，放在独立 crate `packages/journal-sqlite`。

## 理由

1. **审计要能查**：监管检查会问"某笔交易的状态迁移"，SQL 一条语句的事；
   JSONL 要全量读进来自己过滤。
2. **事务性**：入队/出队/记账要么都成要么都不成，文件追加做不到。
3. **bundled 编译**：不依赖系统 SQLite 版本，三平台行为一致（Windows 上没有 DLL 问题）。
4. **单独成包**：`tellerkit-core` 保持零数据库依赖，纯逻辑测试不受影响（宪法第 2 条）。

## 代价

| 代价 | 缓解 |
|---|---|
| 编译时间增加（bundled 编 C） | 只在 journal 包上付一次；core 测试不受影响 |
| 多一个依赖面 | 只用最基本的 SQL，不引 ORM |
| 账本未加密 | P2 做（柜面终端有磁盘加密兜底），先记为已知缺口 |
| 单连接 + Mutex 串行 | 柜面单柜员场景足够；并发下会排队 |

## 被否决的方案

- **JSONL 追加**：事务性与查询都弱，审计场景迟早要换。
- **sled**：纯 Rust 很快，但查询能力弱、社区热度下降，审计 SQL 用不上。
- **放 core 里**：会让纯逻辑层依赖数据库，`cargo test -p tellerkit-core` 变重且不再"无 IO"。
