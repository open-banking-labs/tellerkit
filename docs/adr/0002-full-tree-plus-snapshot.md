# ADR-0002：菜单存全量树，权限存快照

- 状态：已接受
- 日期：2026-11-24

## 背景

不同角色/岗位的菜单不同。直觉做法是"按角色生成菜单包"，但那会带来
N 份包、N 倍下发成本、N 倍的版本一致性问题。

## 决策

- `.mtree` 只存**一份全量菜单树**（所有角色可能看到的节点及父子关系）。
- 登录响应携带 **`PermSnapshot`**（`menuCodes` / `actionCodes` / `permVersion`）。
- 渲染前在内存中递归剪枝：节点自身有权 → 保留；否则只要有任一后代有权 → 保留为容器；否则整枝丢弃。

## 理由

1. 一份包服务所有角色，菜单版本与权限版本彻底解耦，各自独立演进。
2. 剪枝是纯内存操作，实测 < 1ms，对启动速度影响可忽略。
3. "机构新增角色"不需要重新打包菜单，只需要服务端授予不同的 code 集合。

## 关键实现细节

- 叶子/可导航节点的 code 才进 `menuCodes`；分组节点通常不单独授权。
- 父节点无权但子孙有权时，父节点必须保留（否则子菜单会凭空消失）。
  这类节点标记 `direct = false`，前端渲染为不可点击的容器。
- 快照只在内存与登录响应中存在，**不落盘**——避免换账号后残留（见 ADR-0005 的补充）。

## 代价

- 单个包体积略大（全量树 vs 单角色树）：实测 demo 树 ~20 节点，包 < 1KB，可忽略。
- 客户端能读到全部菜单 code（包括无权看到的）。这不构成信息泄露：
  菜单标题不是机密，且服务端鉴权独立。
