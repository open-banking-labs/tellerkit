# ADR-0005：权限快照的生命周期

- 状态：已接受
- 日期：2026-11-24

## 背景

权限快照决定"看到哪些菜单"。如果它的生命周期管错了，后果不是难看，
而是**下一个柜员看到上一个柜员的菜单**——在柜面场景里这是事故。

## 决策

| 时机 | 动作 |
|---|---|
| 登录成功 | 用新快照**替换**旧快照（不是合并） |
| 登出 | 立刻置 `None`，并丢弃已渲染的菜单 |
| 切换账号 | 等价于"登出 + 登录"，旧快照不得复用 |
| 收到 401 | 清快照 + 回到登录页 |
| 应用退出 | 不落盘，不恢复 |

**快照永不写入磁盘。** 只在内存与登录响应里存在。

## 理由

1. 落盘快照会引来"谁在什么时候清了它"的一致性问题；内存快照随进程消亡，最简单也最安全。
2. 菜单包（`.mtree`）是无状态的，可以落盘；权限快照是有状态的，不落盘。
   这条边界一旦混淆，就会出现"换号后菜单残留"的经典 bug。
3. 登录必然有网络（要拿快照），所以"断网启动"只依赖菜单包、不依赖快照——
   断网时用户本来也无法登录，不存在体验损失。

## 实现位置

- `AppState::clear_session()`（`src-tauri/src/lib.rs`）
- `logout` 命令调用它，并让前端回到登录页（`src/App.vue`）
- 测试：`crates/tellerkit-core` 不涉及会话；会话状态由 `src-tauri` 持有，
  验收靠 P0 验收清单第 5 条手工验证

## 已知缺口（P1 补）

- 没有"会话超时自动锁定"，锁屏在 P3。
- 没有并发会话检测（同一柜员在另一台终端登录）。
