# 桌面端职责边界

> 一句话：**账务、账户、授权、记账都在远端核心系统。桌面端只负责"柜员怎么用"和"断网怎么办"。**
> 相关：[docs/architecture.md](architecture.md) · [docs/security-boundary.md](security-boundary.md)

## 1. 为什么要写这个

桌面端最容易失控的地方不是 UI，是**悄悄长出业务逻辑**：
为了让界面快一点，本地算个余额；为了少一次请求，本地判个"够不够扣"；
为了体验顺畅，本地把冲正标成已完成。

每一条单独看都合理，合起来就是一个**与核心系统不一致的第二账本**。
柜面系统的第一原则是"账只有一个地方算"，所以这里把边界写死。

## 2. 桌面端负责（可以做，且应该做）

| 领域 | 具体职责 | 代码位置 |
|---|---|---|
| 会话 | 登录态、权限快照（只读）、离岗锁屏、水印 | `core::session` · `core::perm` · UI |
| 菜单 | 本地包加载、验签、按快照剪枝、版本更新 | `core::{pack,store,sync,filter}` |
| 业务包 | `.bizpkg` 验签、依赖拓扑、菜单合并、模块加载 | `core::pkg` · `PackageHost.vue` |
| 设备 | 打印、读卡、密码键盘、高拍仪、型号白名单 | `core::device` |
| 交易**接入** | 幂等键生成、提交、三态展示、离线挂起、重试调度 | `core::{tx,replay}` · `app::ShellApp` |
| 审计 | 本地留痕（谁、何时、做了什么） | `journal-sqlite` · `app.rs` |
| 通信 | 传输、编解码、路由、主备 | `core::remote` · `transport-net` |
| 更新 | 灰度判定、下载时机、回滚 | `core::update` |
| 界面 | 渲染与交互 | `apps/shell/src` |

## 3. 核心系统负责（桌面端**不得**自行决定）

| 领域 | 为什么不能在客户端 |
|---|---|
| 账户与余额 | 客户端只拿展示用的快照；本地算余额必然与主机漂移 |
| 记账/会计分录 | 入账是核心系统的原子操作，客户端只提交"请求" |
| 利息、手续费、汇率 | 规则随产品与监管变，客户端不应内置 |
| 交易授权/审批结论 | 授权在主机侧校验；客户端收集的是"申请"，不是"结论" |
| 幂等去重 | 客户端只保证**复用同一个键**，去重必须由主机做 |
| 权限授予 | 客户端只按快照剪枝；快照由服务端签发 |
| 对账与报表 | 一致性以核心系统为准 |

## 4. 灰区与判定规则

| 事项 | 客户端做到哪 | 判定依据 |
|---|---|---|
| 冲正 | 收集申请 + 授权人，生成**待确认**记录 | 只有主机回了流水号才算处置完成；本地记录是"意图"不是"结果" |
| 交易状态 | 提交中 / 已提交 / 待重放 / 被拒 | 终态以主机回执为准；客户端不发明状态 |
| 额度校验 | 不做，只展示主机返回的原因 | 本地校验会拦下主机允许的交易，或放过主机拒绝的交易 |
| 离线挂起 | 允许，但要求主机声明幂等 | 见 `contracts/lifecycle.md` 不变量 6/7 |
| 更新灰度 | 客户端算散列决定"谁先更新" | 这是发布策略，不是账务 |

## 5. 允许"本地算"的四类东西

判断标准：**算错了会不会导致账不一致**。不会的，可以本地算。

1. 展示用的排序、过滤、快捷键（错了只是不好用）
2. 超时、退避、重试节奏（错了只是慢或多试几次）
3. 灰度散列、缓存命中（错了只是更新早晚）
4. 本地审计的时间戳与格式化（错了不涉及金额）

## 6. 反模式（评审直接打回）

1. 客户端解析主机返回的余额，再做加减法。
2. 在客户端判断"够不够扣"、"能不能办"。
3. 把冲正/授权**本地标记为完成**，不等主机回执。
4. 客户端自己生成流水号（会让对账时两边对不上）。
5. 为"减少请求"把多个业务规则合并到一次本地计算里。

## 7. 代码层面的约束（`check-boundaries` 强制）

- `packages/core` 里出现 `balance` / `interest` / `accrual` / `fee` / `ledger`（除已有的本地账本适配器外）
  这类词，视为业务逻辑上移，评审必须解释。
- 客户端不得生成流水号：`reference` 只来自主机响应。
- `TxEngine` 的终态只能是 `Committed` / `Pending` / `Rejected`——**没有 `Unknown`**，
  因为"不知道"必须交给主机查证（见 `docs/adr/0007`）。
