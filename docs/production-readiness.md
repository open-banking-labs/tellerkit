# 上生产前置条件

> 状态：**未就绪**。本表是唯一的阻断清单，评审/上线前逐条核对。
> 数字口径见 `npm run stats`；门禁与测试以 `npm run gate` 退出码为准。

## 1. 一句话

桌面端功能面已经闭环（菜单、交易、冲正、重放、审计、对账、包沙箱、更新策略），
**但下面 8 项不解决就不能上生产**。其中 5 项不是代码问题，是环境与流程问题。

## 2. 阻断项

| # | 阻断项 | 现状 | 影响 | 谁来解决 | 验收方式 |
|---|---|---|---|---|---|
| B1 | **服务端幂等未验证** | 客户端已按契约复用幂等键、拒绝离线挂起（`changes/001`），但服务端是否真的去重**没有经过联调** | 未去重 = 重试即重复扣账 | 服务端 + 联调 | 同一键连发 3 次，账上只有 1 笔、流水号相同 |
| B2 | **冲正接口未联调** | `RemoteBanking::reverse` 只有 mock/假后台（`changes/013`） | 状态不明的交易无法真正冲正 | 服务端 | 主机返回流水号后才 `confirm()`，中途失败可重试 |
| B3 | **IAM 未接** | 登录是演示角色；冲正授权固定为"主管 T0101" | 任何人可拿任意角色登录；授权形同虚设 | 行内 IAM | 登录走真实认证；授权走主管凭证/指纹 |
| B4 | **真机外设未验证** | 打印/读卡/密码键盘/扫描全是 mock（`device.rs`） | 不知道真机行为，脱敏与白名单未在硬件上验证 | 硬件 + 驱动 | 四类设备各跑一次完整交易 |
| B5 | **更新执行器未接** | 策略（灰度/高峰/回滚）已实现并有测试；下载、验签、原子替换未接 | 无法发布新版本 | 发布流水线 | 灰度→全量→回滚各演练一次 |
| B6 | **证书吊销缺失** | TLS 已通（rustls + 内置根），无 OCSP/CRL | 私钥泄露后仍可冒用 | 客户端 | 吊销列表生效的负向用例 |
| B7 | **账本密钥未进 OS 钥匙串** | AES-GCM 加密 `tx_queue.elements`，密钥与库同目录（`changes/010`） | 能执行代码者两样一起拿；防的是"只拷走 DB" | 客户端 | 密钥由 DPAPI/Keychain 保管，不落明文文件 |
| B8 | **配置签名私钥的保管** | 配置签名（`changes/008`）已实现，私钥谁持有没定 | 持有者可把端点指向任意地址 | 运维/安全 | 密钥在 HSM 或受控签名服务里 |

## 3. 非阻断但已明示的偏差

| 项 | 偏差 | 依据 |
|---|---|---|
| 对账日界 | `start_of_day` 用 **UTC** 日界，跨时区网点会算错"今天" | `changes/014` |
| 业务包隔离 | iframe 沙箱，**同进程**；侧信道未防 | `security-boundary.md §4.5` |
| 审计只增不可篡改 | 本地 SQLite 可被删；"不可篡改"要靠上报归档 | `changes/006` |
| 自动重放上限 | 默认 5 次后交人工，界面只在重放结果里提一句 | `spec 033` |
| 更新灰度 | 散列按网点，**按版本重新洗牌**（同一网点换版本会被重新抽签） | `update.rs` |

## 4. 上线前必须跑的三件事

```bash
npm run gate          # 六道门禁（含 clippy、轨迹）
npm run stats         # 数字口径，用于对外材料
bash scripts/verify-p0.sh   # 端到端验收
```

加一条人工项：**在目标 Windows 机器上装一版，用真实网络与真实主机跑一笔完整交易**
（提交 → 打印 → 冲正 → 对账）。这一条无法自动化，因为前三项阻断（B1–B3）都在远端。

## 5. 不要说的话

- ❌ "业务包被完全隔离"——同进程，只有 DOM/网络/存储隔离。
- ❌ "账本已加密，安全了"——密钥同目录，防的是单文件泄露。
- ❌ "重试安全"——在 B1 验证之前，只能说"客户端按契约复用幂等键"。
