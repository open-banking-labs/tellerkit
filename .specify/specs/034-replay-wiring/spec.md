# 自动重放接线 · 行为规格

- 能力 ID：`034-replay-wiring`
- 状态：approved（P3.5）

## 背景

`ReplayScheduler`（P3.4）只是策略，没有执行者。`TxEngine::replay_pending` 一次全推，
主机刚恢复时最脆弱，而且失败时无法区分"哪笔该退避"。

## 范围

**做**：单笔重放接口、一轮调度的编排（接管 → 到期 → 逐笔 → 更新退避）。

**不做**：定时触发（由前端/后台任务决定何时 tick）、跨进程锁、与网络状态联动。

## 场景

### S-01 首次运行接管已有挂起交易

```gherkin
GIVEN 引擎里有 2 笔挂起（调度器为空，例如刚重启）
WHEN 跑一轮且主机可用
THEN 两笔都被重放并成功
AND 调度器里不再有它们
```

### S-02 不可达时保留并退避

```gherkin
GIVEN 一笔挂起
WHEN 跑一轮且主机不可达
THEN 仍挂起（不丢单）
AND 退避期内再跑一轮不会重试
```

### S-03 达到上限后放弃自动重试

```gherkin
GIVEN 上限 2 次
WHEN 连续失败 2 次
THEN 该笔进入 gave_up
AND 之后不再自动重试
AND 但仍留在队列里（放弃不等于丢弃）
```

### S-04 手动重放后调度器释放名额

```gherkin
GIVEN 某笔已在调度表里
AND 用户已经手动重放掉了它
WHEN 自动重放跑一轮
THEN 调度表里该笔被移除，不再占名额
```

## 验收标准

- `cargo test -p tellerkit-core replay::` 全绿，覆盖 S-01～S-04
- 放弃用例必须同时断言"不再自动重试"与"仍在队列里"

## 不变量

1. 逐笔重放，不整批推
2. 不可达不丢单
3. 放弃不等于丢弃
