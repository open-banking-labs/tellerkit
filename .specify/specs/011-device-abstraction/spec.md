# 设备抽象 · 行为规格

- 能力 ID：`011-device-abstraction`
- 状态：approved（P1 第二片）
- 关联契约：`contracts/menu-biz-schema.md`（交易元数据声明所需设备）

## 背景

柜面外设（打印机、读卡器、密码键盘、高拍仪）型号杂、驱动各异，且会**中途离线**
（缺纸、被拔掉、超时）。如果业务代码直接调某款打印机，换一批设备就要改交易逻辑。

目标：业务代码只面对 trait；换型号只换适配器；设备不可用时在**交易开始前**就发现，
而不是办到一半才失败。

## 范围

**做**：四个设备 trait、统一的状态与错误模型、就绪校验、mock 实现、敏感数据脱敏。

**不做**：
- 不做真实驱动（P3 真机）
- 不做 Windows USB/串口枚举（P2）
- 不做套打模板渲染（模板格式另行 ADR）

## 场景

### S-01 打印成功并返回作业号

```gherkin
GIVEN 打印机就绪
WHEN 打印一张凭证
THEN 返回作业号与页数
AND 业务代码没有接触任何厂商类型
```

### S-02 设备不可用时给出可操作的错误

```gherkin
GIVEN 打印机未连接或缺纸
WHEN 打印
THEN 返回 DeviceError，说明设备种类与状态
AND 不 panic、不静默成功
```

### S-03 交易开始前校验所需设备

```gherkin
GIVEN 交易声明需要 pinpad 与 printer
AND pinpad 故障
WHEN 校验设备就绪
THEN 拒绝，且指出缺的是哪一类设备
AND 不得执行到"打印已经出纸、但签名没成功"这种半截状态
```

### S-04 敏感数据不外泄

```gherkin
GIVEN 密码键盘返回 PIN 块、读卡器返回卡数据
WHEN 这些值被 Debug 打印或写日志
THEN PIN 块显示为脱敏形式
AND PIN 块**不可被序列化**：Debug 脱敏只挡住日志，序列化仍会输出明文
AND 卡号只保留掩码，完整卡号不出现在结构体里
AND 不足 13 位时整卡掩码（旧的"前 6 后 4"在 10 位时等于没掩码）
```

### S-05 换实现不改业务代码

```gherkin
GIVEN 一段只依赖 Printer trait 的业务函数
WHEN 分别传入正常实现与故障实现
THEN 业务函数代码不变
AND 行为差异只体现在返回值上
```

### S-06 掩码不得因长度变短而退化

```gherkin
GIVEN 卡号长度分别为 9、10、11、12 位
WHEN 构造卡数据
THEN 一律整卡掩码为 ****
AND 13 位起才允许保留前 6 后 4
```

理由：6+4 在 10 位时正好覆盖全部数字，"看起来打了码"但每个数字都可还原。

## 验收标准

- `cargo test -p tellerkit-core device::` 全绿，覆盖 S-01～S-05
- Debug 脱敏用例必须断言**输出字符串**，不能只看字段名

## 不变量

1. 业务代码不得依赖具体设备类型（只允许 `&dyn Printer` 这类 trait 对象）
2. 设备就绪校验必须发生在任何副作用之前
3. 完整卡号与 PIN 块不得进入日志、错误信息或 Debug 输出
